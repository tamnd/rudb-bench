How to read this

Nothing here is a published ClickBench or TPC-H result. Reporting rule seven says a number from one machine is never compared against a number from another, and no machine this project owns is the c6a.4xlarge the public ClickBench board reports on. What this page is for is the shape: the same suite, the same engines and the same five sizes, measured within an afternoon of each other, which is the only way to tell a fixed cost from a per row one.

Hot query time is what the engine itself says the queries took, added over the hot runs, which is the same number the public board publishes. Every run is a fresh process, so hot means the page cache is warm and the buffer pool is not, and no query's number depends on the one before it. The median of at least five runs is what is reported, per reporting rule two.

Ratios are taken over the queries every engine measured. An engine that cannot express a query, or that ran out of time on one, would otherwise be compared on a different set of queries from everybody else. The count is in the table above, per rung.

Load and on disk mean two different things per engine. DuckDB and ClickHouse convert the Parquet into a format of their own and pay for the decode once, at load time, in a column you can see. DataFusion, Polars and rudb read the Parquet where it lies, which is an empty load column and a decode inside every query time beside it. A cell that is the source Parquet rather than the engine's own files is marked in the table.

The suites, the machines, the reporting rules and the three committed artifacts are described in the rudb-bench README. Every rung here has a full per query report beside it in reports/.
